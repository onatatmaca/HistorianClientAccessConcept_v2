HistorianSyncTool — Technical Documentation

A Windows Forms tool for GE Proficy Historian dual-server synchronization · .NET Framework 4.8 / C# / x86
Production ready

This document describes how the HistorianSyncTool application is structured, what each file does, and how the major user-facing flows work end-to-end. It is written for engineers who need to understand the codebase well enough to extend it, debug it, or explain it.

Use the sidebar to navigate, or press Ctrl+K to filter the table of contents. For a printable copy, open File → Print in your browser — the print stylesheet hides the sidebar, starts each major section on a new page, and forces diagrams to fill the page width.

1. Overview

1.1 Purpose

HistorianSyncTool is a desktop application that connects to two GE Proficy Historian servers (a Primary and a Secondary) and provides four related capabilities:

  1. Browse the available tags on both servers and view samples side-by-side.
  2. Compare a tag between the two servers, timestamp-aligned, highlighting mismatched or missing samples.
  3. Analyze gaps in either server's historical data over a user-selected window, visualizing coverage with bars and a detailed gap grid.
  4. Backfill missing samples from one server to the other — either manually (one-shot) or on a fixed schedule (unattended).

The application is built around a layered design that separates UI, services, and data models, with pure-logic helpers extracted as testable seams. The synchronization core uses direct timestamp comparison between the two servers so it catches isolated missing samples regardless of duration, and every batch write is gated on a read-after-write verification.

2. Architecture

2.1 Dual-server model

The application always operates against two Historian instances. They are treated symmetrically in the API surface but have distinct roles in practice:

RoleFieldConvention
Primary_connections.PrimaryAuthoritative data source
Secondary_connections.SecondaryRedundant / mirror server

Both are wrapped in ServerConnection objects, owned by HistorianConnectionService. Most operations require both connections. The secondary hostname is conventionally derived from the primary — when a primary hostname ends with PC2, the secondary strips that suffix; otherwise PC2 is appended.

2.2 Layered design

The codebase is organized in four conceptual layers. The dependency rule is one-directional: Forms depend on Services, Services depend on Models. Services never reference WinForms controls — there's no using System.Windows.Forms; in any service file.

2.4 UI thread / async pattern

All long-running operations follow the same pattern to keep the UI responsive and prevent re-entrancy:

Forms/MainForm.cscanonical pattern
private async void btnSomething_Click(object sender, EventArgs e)
{
    SetBusy(true, "What I'm doing…");   // disables action buttons, shows marquee
    try
    {
        ResetCts();                      // disposes previous CTS, allocates new
        var token = _cts.Token;

        // Capture ALL UI values up front so the worker never touches controls
        DateTime from = dtpStart.Value;
        DateTime to   = dtpEnd.Value;
        string   tag  = cboPrimary.Text;

        var result = await Task.Run(() =>
        {
            token.ThrowIfCancellationRequested();
            return _data.ReadRawInRange(_connections.Primary, tag, from, to);
        }, token);

        // Back on the UI thread: update controls directly
        UpdateGrid(result);
        SetStatus($"Read {result.Count} samples.");
    }
    catch (OperationCanceledException) { SetStatus("Cancelled."); }
    catch (Exception ex)                { SetStatus($"Failed: {ex.Message}", true); }
    finally { SetBusy(false); }
}
Rule Worker code inside Task.Run must never touch Control properties directly. UI values are captured into locals before Task.Run; updates back to the UI go through Invoke (status/log helpers handle this internally).

The ResetCts() helper exists because each long operation needs its own CancellationTokenSource. Without disposal, repeated operations would leak CTS instances, which would gradually leak finalizable resources:

Forms/MainForm.cs
private void ResetCts()
{
    try { _cts?.Dispose(); } catch { }
    _cts = new CancellationTokenSource();
}

The ExecuteBackfill core (direct timestamp comparison)

This is the most important method in the application. It does not use gap windows — it reads both servers' samples for the full evaluation range and copies the timestamps that are present on source but missing on target. This catches isolated missing samples that interval-based gap detection would skip.

Step 1 — read both servers, compute the missing-timestamp diff, and group the missing samples into write batches:

Forms/MainForm.csExecuteBackfill — diff & group
// Read both servers for the full eval range
var srcData = _data.ReadRawInRange(sourceConn, tag, evalFrom, evalTo);
var tgtData = _data.ReadRawInRange(targetConn, tag, evalFrom, evalTo);

// Direct-comparison diff: timestamps on source but not on target
var tgtTicks = new HashSet<long>(tgtData.Select(s => s.Time.Ticks));
var missing = srcData
    .Where(s => !tgtTicks.Contains(s.Time.Ticks))
    .OrderBy(s => s.Time)
    .ToList();

if (missing.Count == 0)
{
    Log($"  {tag}: already in sync ({srcData.Count}/{tgtData.Count}).");
    continue;
}

// Group missing samples into batches by the configured bucket duration
var batches = SampleBucketer.GroupByBucket(missing, batchSize);

Step 2 — write each batch (preserving per-sample quality) and verify it with a read-after-write check before counting it as succeeded:

Forms/MainForm.csExecuteBackfill — write & verify
foreach (var batchSamples in batches)
{
    var times     = batchSamples.Select(s => s.Time).ToArray();
    var values    = batchSamples.Select(s => s.Value).ToArray();
    var qualities = batchSamples.Select(s =>
        s.Quality >= 100.0 ? DataQuality.Good :
        s.Quality > 0      ? DataQuality.Uncertain :
                             DataQuality.Bad).ToArray();

    var errors = _data.WriteFloatSamplesWithQuality(targetConn, tag, times, values, qualities);
    bool writeOk = errors.Count == 0;

    // Verify: re-read the batch's time range. Widen ±1s to tolerate Historian's
    // second-level timestamp rounding (a write at 12:54:30.123 is stored as
    // 12:54:30, so a tick-tight query starting at .123 finds nothing).
    bool verifyOk = true;
    if (writeOk)
    {
        DateTime vStart = times[0].AddSeconds(-1);
        DateTime vEnd   = times[times.Length - 1].AddSeconds(1);
        var verify = _data.VerifyWrite(targetConn, tag, vStart, vEnd, times.Length);
        if (verify.Actual < verify.Expected)
        {
            verifyOk = false;
            tagResult.Errors.Add($"Batch {batchIdx}: verify mismatch — " +
                                 $"wrote {verify.Expected}, found {verify.Actual}");
        }
    }

    if (writeOk && verifyOk)
    {
        tagResult.BatchesSucceeded++;
        tagResult.SamplesWritten += batchSamples.Count;
    }
    else
    {
        tagResult.BatchesFailed++;
    }
}
Why direct comparison Gap-window-based backfill hides isolated missing samples — a 20-second gap on Secondary while Primary has a sample. The MinimumGapSeconds floor (needed to suppress deadband noise) would also suppress real isolated-sample gaps. The direct timestamp diff has no floor; it copies exactly what's missing regardless of duration. A reference snapshot of the older gap-window implementation lives under _backup/batch-based-backfill-phase6/ in case a future change ever needs to revert.

Unattended mode

Three optional parameters let the same method drive scheduled runs:

Pagination pattern

Proficy's paginated query exits on the final page but the final page is in the out parameter. You must AddRange once more after the loop.

Services/HistorianDataService.cs
public List<Tag> BrowseTags(ServerConnection conn, string tagnameMask)
{
    return RetryHelper.Retry(() =>
    {
        TagQueryParams query = new TagQueryParams { PageSize = 100 };
        query.Criteria.TagnameMask = string.IsNullOrWhiteSpace(tagnameMask) ? "*" : tagnameMask;
        query.Criteria.DataType = Tag.NativeDataType.Float;

        List<Tag> allTags = new List<Tag>();
        List<Tag> page;
        while (conn.ITags.Query(ref query, out page))
            allTags.AddRange(page);
        allTags.AddRange(page);    // ← final page after exit — required!
        return allTags;
    }, _maxRetries);
}

Parsing seam (SampleFilter integration)

Read methods convert the Proficy DataSet into a stream of (DateTime, object, double) tuples via a private generator, then hand off to SampleFilter for parsing and clipping. This isolates Proficy types to one tight loop and keeps the parsing logic unit-testable.

Services/HistorianDataService.cs
public List<(DateTime Time, float Value, double Quality)> ReadRawInRange(
    ServerConnection conn, string tagName, DateTime start, DateTime end)
{
    return RetryHelper.Retry(() =>
    {
        DataQueryParams query = new RawByTimeQuery(start, tagName) { … };
        DataSet all  = new DataSet();
        DataSet page = new DataSet();
        ItemErrors errors;
        while (conn.IData.Query(ref query, out page, out errors))
            all.AddRange(page);
        all.AddRange(page);
        return SampleFilter.ParseAndClip(IterateDataSet(all, tagName), start, end);
    }, _maxRetries);
}

private static IEnumerable<(DateTime Time, object Value, double Quality)> IterateDataSet(
    DataSet set, string tagName)
{
    if (set == null || !set.ContainsKey(tagName)) yield break;
    for (int i = 0; i < set.TotalSamples; i++)
        yield return (
            set[tagName].GetTime(i),
            set[tagName].GetValue(i),
            set[tagName].GetQuality(i).PercentGood()
        );
}

Write-with-quality grouping

Proficy's DataSamples<float> has a single ImplicitQuality for the whole batch. To preserve per-sample quality, the method groups indices by quality and writes each group separately.

5.3 GapAnalysisService

File: Services/GapAnalysisService.cs

Pure logic — detects gaps in a sample-time list and plans per-batch backfill windows. No Proficy or WinForms dependencies. The most extensively tested service.

Detection algorithm

  1. Compute deltas between consecutive samples.
  2. ExpectedInterval = Median(deltas) — robust to outliers.
  3. threshold = max(median × 1.5, MinGapDuration) — floor protects deadband-logged tags.
  4. Emit a GapWindow for any consecutive pair where delta > threshold.
  5. Also emit leading + trailing gaps if data doesn't span the full evaluation window.
  6. Empty server: emit one whole-period gap so backfill can target it.
  7. Each gap is split into GapBatch objects of BatchSize duration.
Services/GapAnalysisService.csthreshold + empty-server
result.ExpectedInterval = Median(deltas);

    Math.Max(medianBasedTicks, _minGapDuration.Ticks));

if (!result.HasData && hasEvalPeriod)
{
    var window = new GapWindow { Start = evalFrom, End = evalTo };
    window.Batches = PlanBatches(window.Start, window.End);
    result.Gaps.Add(window);

Backfill feasibility

For each batch in each gap, the opposite server's samples are checked: if at least one sample falls inside the half-open [batch.Start, batch.End) interval, the batch is marked CanBackfill = true. Used to color batches in the gap grid; not used by the direct-comparison backfill code path.

Services/GapAnalysisService.cs
public void MarkBackfillFeasibility(GapAnalysisResult result, List<DateTime> otherServerSamples)
{
    var sorted = new List<DateTime>(otherServerSamples);
    sorted.Sort();
    foreach (var gap in result.Gaps)
        foreach (var batch in gap.Batches)
        {
            int idx = sorted.BinarySearch(batch.Start);
            if (idx < 0) idx = ~idx;
            batch.CanBackfill = idx < sorted.Count && sorted[idx] < batch.End;
        }
}

5.4 RetryHelper

File: Services/RetryHelper.cs

Pure retry-with-backoff. Extracted as a static helper so it can be unit tested with an injected sleep delegate — no real waiting in tests, no Proficy dependency.

Services/RetryHelper.cs
public static T Retry<T>(
    Func<T> action,
    int maxAttempts,
    int[] delaysMs = null,
    Action<int> sleep = null)
{
    delaysMs = delaysMs ?? DefaultDelaysMs;     // { 500, 1000, 2000 }
    sleep    = sleep    ?? Thread.Sleep;

    Exception last = null;
    for (int attempt = 0; attempt < maxAttempts; attempt++)
    {
        try { return action(); }
        catch (Exception ex)
        {
            last = ex;
            if (attempt < maxAttempts - 1 && attempt < delaysMs.Length)
                sleep(delaysMs[attempt]);
        }
    }
    throw new InvalidOperationException(
        $"Operation failed after {maxAttempts} attempts: {last?.Message}", last);
}

5.5 SampleFilter

File: Services/SampleFilter.cs

Pure tuple-stream parser. Drops nulls and unparseable entries, optionally clips to a half-open [start, end) interval. The break on out-of-range time relies on chronological input from the Historian.

Services/SampleFilter.cs
public static List<(DateTime Time, float Value, double Quality)> ParseAndClip(
    IEnumerable<(DateTime Time, object Value, double Quality)> raw,
    DateTime start, DateTime end)
{
    var result = new List<(DateTime, float, double)>();
    if (raw == null) return result;
    foreach (var s in raw)
    {
        if (s.Time >= end) break;          // half-open: end is OUT
        if (s.Time < start) continue;      // half-open: start is IN
        if (s.Value == null) continue;
        float v;
        if (!float.TryParse(s.Value.ToString(), out v)) continue;
        result.Add((s.Time, v, s.Quality));
    }
    return result;
}

5.6 SampleBucketer

File: Services/SampleBucketer.cs

Groups a sorted sample list into buckets where each bucket spans up to bucketSize from its first sample's time. Bucket-start resets to the next sample's time when the spacing exceeds bucketSize.

Services/SampleBucketer.cs
public static List<List<(DateTime, float, double)>> GroupByBucket(
    List<(DateTime Time, float Value, double Quality)> sorted, TimeSpan bucketSize)
{
    var result = new List<List<(DateTime, float, double)>>();
    if (sorted == null || sorted.Count == 0) return result;

    var current = new List<(DateTime, float, double)> { sorted[0] };
    DateTime bucketStart = sorted[0].Time;

    for (int i = 1; i < sorted.Count; i++)
    {
        if (sorted[i].Time - bucketStart < bucketSize)
            current.Add(sorted[i]);
        else
        {
            result.Add(current);
            current     = new List<(DateTime, float, double)> { sorted[i] };
            bucketStart = sorted[i].Time;     // reset, not advance
        }
    }
    if (current.Count > 0) result.Add(current);
    return result;
}

5.7 ScheduleService

File: Services/ScheduleService.cs

Owns a 15-second polling System.Windows.Forms.Timer that triggers a delegate when the next-run instant has elapsed. The work itself is delegated — this class only handles cadence, gating, and next-run bookkeeping.

Gating rules

Ignore Tick events when:

  • Service is disabled.
  • A run is already in flight.
  • Now is before NextRunUtc.

Next-run computation

Services/ScheduleService.cs
private void ComputeNextRun()
{
    var nowUtc = DateTime.UtcNow;

    // Never ran (or last-run ancient) → first run one interval out.
    if (_lastRunUtc < nowUtc.AddDays(-7))
    {
        _nextRunUtc = nowUtc.AddMinutes(_intervalMinutes);
        return;
    }

    // Schedule next interval after last completed run. If we missed several
    // intervals (laptop asleep), don't replay a backlog — kick one off in 30s.
    _nextRunUtc = _lastRunUtc.AddMinutes(_intervalMinutes);
    if (_nextRunUtc < nowUtc) _nextRunUtc = nowUtc.AddSeconds(30);
}
